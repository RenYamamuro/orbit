# Orbit（サブスク・固定費マネージャー）

サブスクと毎月の固定費を管理するアプリ。ビルド不要の静的サイトで、置くだけで動きます。

## 公開先

https://renyamamuro.github.io/orbit/

GitHub Pages で公開している。更新は `git push` するだけで反映される（反映まで数十秒）。

```bash
git add -A && git commit -m "変更内容" && git push
```

- 端末に届いたかは、アプリを一度閉じて開き直すと分かる（2回目の起動で新しい版に切り替わる）。
- デプロイのたびに `sw.js` の `VERSION` を上げること（上げないと端末側のキャッシュが入れ替わらない）。
- GitHub Pages は `Cache-Control: max-age=600` を返すので、`sw.js` は HTML・JS・CSS を
  取りに行くときに HTTP キャッシュを迂回している（迂回しないと最大10分古い版が届く）。

以前は Netlify（subscriptionmanagement-app.netlify.app）で公開していた。

### 覚えておくこと（つまずいた箇所）

- **URL を変えたら、Firebase の承認済みドメインに新しいドメインを登録し直す。**
  Firebase コンソール → Authentication → 設定 → 承認済みドメイン。
  登録しないと Google ログインが必ず失敗します。GitHub Pages では `renyamamuro.github.io`。
- **データは URL（ドメイン）ごとに別々に保存される。**
  URL を変えると新しい URL では空から始まるので、同期で戻す（サインインするだけで戻る）。
- **初めて同期するときは、データが入っている端末から先にサインインする。**
  空の端末を先に繋ぐと、空の状態がクラウドに上がります
  （確認ダイアログで止まるようにしてありますが、順序を守れば出ません）。
- **ホーム画面のアイコンは追加した時点で固定される。**
  変えたいときは削除して追加し直します。

## 1. どこかに置く（どの端末からでも開けるようにする）

### GitHub Pages（今の公開方法）

1. GitHub で新しいリポジトリを作る（Public。無料プランで Pages を使うには公開リポジトリが必要）
2. このフォルダの中身を push する
3. Settings → Pages → Source を「Deploy from a branch」、`main` ブランチの `/ (root)` に設定
4. `https://ユーザー名.github.io/リポジトリ名/` で開けます

### Netlify Drop を使う場合

1. https://app.netlify.com/drop を開く
2. このフォルダごとブラウザにドラッグ＆ドロップ
3. `https://〇〇.netlify.app` の URL が出ます。サイトは「公開」にしておく
   （非公開だとアイコンやマニフェストの取得までログイン画面が返り、ホーム画面のアイコンが崩れる）

どちらも **HTTPS** で配信されます。オフライン動作とホーム画面への追加には HTTPS が必要なので、
`file://` で直接開く運用からは卒業してください。

## 2. ホーム画面に追加する（アプリのように使う）

- **iPhone / iPad（Safari）**：共有ボタン → 「ホーム画面に追加」
- **Android（Chrome）**：メニュー → 「アプリをインストール」
- **Mac / Windows（Chrome・Edge）**：アドレスバー右のインストールアイコン

追加すると、ブラウザのバーが消えて全画面で開き、**オフラインでも起動します**。

## 3. 端末間でデータを同期する（任意）

同期を使わない場合、データは各ブラウザの中だけに保存されます（外部に一切送信されません）。
複数端末で同じデータを見たい場合だけ、以下を設定してください。

### Firebase の準備（無料・10分ほど）

1. https://console.firebase.google.com/ で **プロジェクトを作成**
   （Google アナリティクスは「無効」で構いません）
2. 左メニュー **構築 → Firestore Database** → 「データベースの作成」
   - ロケーションは `asia-northeast1`（東京）
   - モードは **本番環境モード** を選ぶ
3. **Firestore の「ルール」タブ**を開き、次の内容に置き換えて「公開」
   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /users/{uid}/{document=**} {
         allow read, write: if request.auth != null && request.auth.uid == uid;
       }
     }
   }
   ```
   これで **自分のデータには自分しかアクセスできません**。
4. 左メニュー **構築 → Authentication** → 「始める」 → **Google** を有効にする
5. Authentication → 「設定」タブ → **承認済みドメイン** に、
   手順1で取得した公開URLのドメイン（例 `ユーザー名.github.io`）を追加
6. プロジェクトの概要（歯車）→ **プロジェクトの設定** → 「マイアプリ」で
   **ウェブアプリ（`</>`）を追加** し、表示された `firebaseConfig = { … }` をコピー

### アプリ側の設定

1. サイドバーの「バックアップと復元」を開く
2. 「同期の設定（初回のみ）」を開き、コピーした `firebaseConfig` を貼り付けて **保存して接続**
3. **Google でサインイン**

2台目以降も、同じ設定を貼って同じ Google アカウントでサインインすれば繋がります。

### 同期の仕様と注意

- 変更のたびに自動で送信され、他の端末には即座に反映されます
- 競合は **更新時刻が新しいほうを採用** します。2台で同時に別々の編集をすると、
  あとから保存されたほうで上書きされます（消えた側は「履歴から戻す」で復元できます）
- オフラインのときはローカルに保存され、オンラインに戻ったときの次の変更で送信されます

## 4. データの持ち出し

- 「バックアップと復元」→ **ファイルに書き出す** で JSON を保存
- 別の端末では **ファイルから読み込む** で復元
- Chrome / Edge では保存先ファイルを指定して**自動バックアップ**もできます
